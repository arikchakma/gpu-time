## 2. Tooling choices (ladder: what is already here first)

| Need | Choice | Why |
|---|---|---|
| Runtime for scripts | **bun** (installed) for generator/featurizer (fast TS, no build step); Node 24 for tests and publish | Same TypeScript tokenizer runs in generator and browser → zero train/inference skew |
| Bundler | **esbuild** | What gpu-lexer uses; single-file ESM, minify, mangle |
| WGSL minify | **wgslender** | What gpu-lexer uses |
| Tests | **vitest** + **Playwright** (Chrome, WebGPU) | Browser parity tests need a real GPU |
| Training | **uv** + **PyTorch (MPS)** on the M4 Max | Model is ~33K params; a full run is minutes, not hours |
| Timezones | built-in `Intl.DateTimeFormat` | Avoids a 130 KB polyfill; Node 24 and all target browsers have full ICU |
| Formatting | prettier | — |
| Runtime deps | **none** | Like gpu-lexer |

Dev deps only: typescript, esbuild, wgslender, vitest, playwright, prettier, tsx (fallback if bun misbehaves), rrule (test oracle only), the baseline libraries (bench only), ts-json-schema-generator.

## 4. Size budget (enforced by scripts/build.ts, build fails when exceeded)

| Part | Budget (brotli) | Rationale |
|---|---|---|
| weights string + scales | 16 KB | 32.7K params × 0.5 B/param (gpu-lexer ratio) ≈ 14 KB |
| tokenizer + decode + cpu inference | 3 KB | ~250 lines |
| gpu runtime + minified WGSL | 5 KB | gpu-lexer's runtime+shader is 8.2 KB gzip with 7 kernels; ours has 1 |
| compile + lexicon | 4 KB | ~500 lines |
| resolve + rrule + zoned | 4 KB | ~400 lines |
| **Total** | **≤ 30 KB brotli** (≈ 36 KB gzip) | chrono-node 44 KB gz, compromise-dates 180 KB gz |

`./resolve` is a separate export so a consumer who only wants the schedule JSON does not pay for the resolver.

## 5. Acceptance criteria

- `bun scripts/build.ts` produces `dist/` and `dist/size.json`, fails above budget.
- `vitest run` runs with an empty test.
- `uv run --project training python -c "import torch; print(torch.backends.mps.is_available())"` prints True.
- CI-less for now; a `make all` equivalent (`bun run all`) chains gen → featurize → train → export → build → test → bench.
